# 📘 01 · การพัฒนาในยุค AI ด้วย Claude Code บน VS Code

**เวลา:** 09.30–10.50 (M0 20 นาที + M1 60 นาที)
**ผลลัพธ์:** เข้าใจวิธีทำงานแบบ "มนุษย์กำหนดทิศ–AI ลงมือ–มนุษย์ตรวจ" และสร้างแอปแรกจาก prompt ได้ใน 30 นาที

---

## 🌏 M0 · ภาพรวม (20 นาที)

### 📈 1. เกิดอะไรขึ้นกับการพัฒนาซอฟต์แวร์

| ยุค | คนทำอะไร | เครื่องมือทำอะไร |
|---|---|---|
| ก่อน 2022 | เขียนทุกบรรทัด ค้น Stack Overflow | editor ช่วยเติมคำ |
| 2023–2024 | ถาม chatbot แล้ว copy โค้ดมาวาง | AI ตอบเป็นชิ้น ๆ ไม่เห็นทั้งโปรเจกต์ |
| 2025– | **กำหนดเป้าหมาย ทบทวน ตัดสินใจ** | **AI agent อ่านทั้งโปรเจกต์ แก้หลายไฟล์ รันคำสั่ง ทดสอบเอง** |

ทักษะที่มีค่าขึ้น: **การแตกปัญหา, การเขียนสเปกที่ชัด, การอ่าน/ตรวจโค้ด, ความเข้าใจระบบ (architecture)**
ทักษะที่มีค่าลดลง: การจำ syntax, การพิมพ์ boilerplate

### 🎯 2. "ศูนย์กลางการสร้างสรรค์" ของวันนี้

```text
                ┌──────────────────────────────┐
                │   VS Code + Claude Code      │  ← คิด / สั่ง / ตรวจ
                └──────┬───────────────┬───────┘
                       │               │
           ┌───────────▼───┐     ┌─────▼──────────┐
           │ Docker Desktop│     │ GitHub Desktop │
           │ "รันได้ทุกที่"   │     │ "ไม่หาย ส่งต่อได้" │
           └───────┬───────┘     └─────┬──────────┘
                   │                   │
     ┌─────────────▼───────────────────▼──────────────┐
     │  Node-RED  │   n8n (เลขาส่วนตัว)  │  Agent App   │
     └────────────────────────────────────────────────┘
```

- **Claude Code** = ช่างฝีมือ (ทำงานเร็ว แต่ต้องมีแบบ)
- **Docker** = ห้องทำงานสำเร็จรูป (ยกไปตั้งที่ไหนก็เหมือนเดิม)
- **Git/GitHub** = สมุดบันทึกทุกการเปลี่ยนแปลง (ย้อนได้ ส่งต่อได้ ทำงานร่วมกันได้)

### 🎬 3. เดโมปลายทาง (5 นาที)

วิทยากรเปิด Agent App (http://localhost:3000) แล้วพิมพ์:

> "สรุปงานค้างของฉัน แล้วส่งแจ้งเตือนเรื่องที่ด่วนที่สุดเข้า Telegram"

ให้ผู้เรียนเห็นว่า agent **คิด → เรียก tool → ได้ผล → เรียก tool ต่อ → ตอบ** และบอกว่า "บ่ายนี้ทุกคนจะสร้างสิ่งนี้เอง"

## 🧠 M1 · Claude Code บน VS Code (60 นาที)

### ✨ 1. Claude Code ทำอะไรได้บ้าง

| ความสามารถ | ตัวอย่างคำสั่ง |
|---|---|
| อ่านและอธิบายโปรเจกต์ | "อธิบายโครงสร้าง repo นี้ ไฟล์ไหนคือ entry point" |
| สร้าง/แก้หลายไฟล์พร้อมกัน | "เพิ่มหน้า login และ API /auth ให้ครบ" |
| รันคำสั่งใน terminal | "รัน test แล้วแก้จนผ่าน" |
| แก้บั๊กจาก error | วาง error log แล้วพิมพ์ "แก้ให้หน่อย อธิบายสาเหตุด้วย" |
| ทำงานกับ Git | "สรุปสิ่งที่เปลี่ยนแล้วเขียน commit message" |
| ทำงานกับ Docker | "เขียน Dockerfile และ docker-compose สำหรับแอปนี้" |
| อ่านรูปภาพ | ลากภาพหน้าจอ UI/ER diagram เข้ามาแล้วสั่ง "ทำให้เหมือนภาพนี้" |

### 🖥️ 2. ส่วนประกอบสำคัญของหน้าจอ

- **แผง Claude** (ไอคอน ✱ ที่ sidebar หรือ `Ctrl+Esc`) — ช่องแชทกับ agent
- **@-mention ไฟล์** — พิมพ์ `@` แล้วเลือกไฟล์ เพื่อชี้ให้ดูไฟล์นั้นโดยตรง
- **Selection context** — เลือกโค้ดใน editor แล้วถาม Claude จะเห็นส่วนที่เลือก
- **Diff view** — ทุกการแก้ไฟล์จะแสดงเป็น diff ให้กด Accept/Reject
- **Permission modes** — ขอสิทธิ์ทุกครั้ง / อนุญาตแก้ไฟล์อัตโนมัติ / **Plan mode** (คิดอย่างเดียว ยังไม่แก้)

### 🔄 3. วงจรการทำงาน 4 จังหวะ (หัวใจของโมดูลนี้)

```text
  ① Explore  →  ② Plan  →  ③ Build  →  ④ Verify
  "อ่านก่อน"     "วางแผน"     "ลงมือ"      "พิสูจน์ว่าใช้ได้"
       ▲                                   │
       └───────────── วนซ้ำเป็นรอบเล็ก ๆ ───────┘
```

| จังหวะ | ทำอะไร | prompt ตัวอย่าง |
|---|---|---|
| ① Explore | ให้ Claude อ่านและเล่าก่อน **ยังไม่แก้อะไร** | "อ่านโปรเจกต์นี้แล้วสรุปว่ามีอะไรอยู่แล้วบ้าง ยังไม่ต้องแก้" |
| ② Plan | ใช้ **Plan mode** ให้เสนอแผน แล้วเรา **แก้แผน** ก่อนอนุมัติ | "วางแผนเพิ่มฟีเจอร์ X แบ่งเป็นขั้น บอกไฟล์ที่จะแตะ" |
| ③ Build | อนุมัติทีละขั้น ไม่ใช่ทั้งหมดในครั้งเดียว | "ทำขั้นที่ 1 ก่อน" |
| ④ Verify | ให้ **รันจริง** และ **เขียน test** ไม่ใช่แค่บอกว่า "น่าจะใช้ได้" | "รันแอปแล้ว curl ทดสอบ endpoint ทุกตัว แสดงผลให้ดู" |

> [!TIP]
> 🏅 **กฎทอง:** งานที่ Claude ตรวจสอบเองได้ (มี test, รันได้, มี error ให้อ่าน) จะได้คุณภาพสูงกว่างานที่ต้องเดาเสมอ — **ออกแบบงานให้ตรวจสอบได้**

### ✍️ 4. เขียน prompt แบบสถาปนิก

prompt ที่ดี = **บริบท + เป้าหมาย + ข้อจำกัด + เกณฑ์ว่าเสร็จ**

❌ "ทำเว็บจองห้องประชุมให้หน่อย"

✅
```text
สร้างเว็บจองห้องประชุมสำหรับอุทยานวิทยาศาสตร์ (ผู้ใช้ ~50 คน ใช้ภายใน)
- Node.js + Express, เก็บข้อมูลใน SQLite, หน้าเว็บ HTML ธรรมดาไม่ใช้ framework
- ห้อง 3 ห้อง จองเป็นช่วง 30 นาที ห้ามจองซ้อน
- ต้องรันด้วย `npm start` ได้ทันที และมี test สำหรับกติกาห้ามจองซ้อน
เสร็จเมื่อ: test ผ่าน และเปิด http://localhost:3000 จองได้จริง
วางแผนก่อน ยังไม่ต้องเขียนโค้ด
```

### 📝 5. CLAUDE.md — ความจำถาวรของโปรเจกต์

ไฟล์ `CLAUDE.md` ที่ราก repo ถูกโหลดเข้าบริบทของ Claude **ทุกครั้ง** ใช้เก็บสิ่งที่ "อ่านโค้ดแล้วไม่รู้"

ควรมี:
- คำสั่งรัน / ทดสอบ / build
- ข้อตกลงของทีม (ภาษา comment, การตั้งชื่อ, library ที่อนุญาต)
- สิ่งที่ห้ามทำ (เช่น "ห้ามแก้ไฟล์ใน `legacy/`", "ห้าม commit `.env`")
- ศัพท์เฉพาะขององค์กร

ไม่ควรมี: สิ่งที่อ่านจากโค้ดได้อยู่แล้ว, คำอธิบายยาวเหยียด, ความลับ

สร้างเร็ว: พิมพ์ `/init` ให้ Claude สำรวจและร่างให้ แล้วเรา **ตัดให้สั้น** · ดูตัวอย่างจริงที่ [CLAUDE.md](../CLAUDE.md) ของ repo นี้

### ⌨️ 6. คำสั่งและฟีเจอร์ที่ควรรู้

| คำสั่ง / ฟีเจอร์ | ใช้เมื่อ |
|---|---|
| `/init` | เริ่มโปรเจกต์ใหม่ ให้ร่าง CLAUDE.md |
| `/clear` | เปลี่ยนเรื่อง — ล้างบริบทเก่าที่ไม่เกี่ยว (คุณภาพดีขึ้น ประหยัดขึ้น) |
| `/compact` | บทสนทนายาวมาก ย่อบริบทแต่เก็บสาระ |
| Plan mode | งานใหญ่ / งานที่แตะหลายไฟล์ / งานที่ยังไม่แน่ใจแนวทาง |
| `/review` หรือ `/code-review` | ให้รีวิวการเปลี่ยนแปลงก่อน commit |
| **Skills** | ชุดคำสั่งสำเร็จรูปขององค์กร (เช่น มาตรฐาน CI, การทำ Google Sign-In) |
| **Hooks** | กติกาที่ระบบบังคับ เช่น "หลังแก้ไฟล์ให้รัน formatter ทุกครั้ง" |
| **MCP servers** | ต่อ Claude เข้ากับระบบอื่น (ฐานข้อมูล, Jira, Figma, Google Drive) |
| **Subagents** | แยกงานค้นคว้า/รีวิวให้ agent ย่อย เพื่อไม่ให้บริบทหลักรก |

### ⚠️ 7. ข้อควรระวัง (ต้องพูดทุกรุ่น)

1. **AI มั่นใจได้แม้ผิด** — อ่าน diff ทุกครั้งก่อน Accept โดยเฉพาะเรื่อง auth, เงิน, การลบข้อมูล
2. **ความลับ** — อย่าวาง API key / รหัสผ่าน / ข้อมูลส่วนบุคคลจริงในแชท ใช้ `.env` + `.gitignore`
3. **PDPA** — ข้อมูลส่วนบุคคลที่ส่งเข้า AI ต้องผ่านการพิจารณาตามนโยบายองค์กร
4. **สิทธิ์การรันคำสั่ง** — อย่าอนุญาตคำสั่งที่ลบ/เขียนทับแบบกว้าง ๆ (`rm -rf`, `git push --force`) อัตโนมัติ
5. **ความเข้าใจคือความรับผิดชอบ** — โค้ดที่เราไม่เข้าใจ = หนี้ที่องค์กรต้องจ่ายภายหลัง ให้ Claude อธิบายจนเราเข้าใจ

## 🧪 Lab 1 · แอปแรกจาก prompt (30 นาที)

**โจทย์:** สร้าง "ระบบบันทึกงานประจำวัน" (Task Log) สำหรับทีมอุทยานฯ

1. สร้างโฟลเดอร์ใหม่ `my-tasklog` → VS Code: **File → Open Folder**
2. เปิดแผง Claude เปิด **Plan mode** แล้วใช้ prompt จาก [prompts/prompt-cards.md](../prompts/prompt-cards.md) การ์ด **L1-1**
3. อ่านแผน → **แก้แผนอย่างน้อย 1 จุด** (เช่น "เพิ่มช่องสถานะ: todo/doing/done") → อนุมัติ
4. ให้ Claude สร้างและ **รันจริง** → เปิดเบราว์เซอร์ทดสอบ
5. สั่ง `/init` ให้สร้าง `CLAUDE.md` แล้วตัดเหลือไม่เกิน 20 บรรทัด
6. ขอฟีเจอร์เพิ่ม 1 อย่างด้วยตัวเอง (เช่น export CSV, ค้นหา, กรองตามสถานะ)

**เช็กลิสต์ผ่าน Lab:**
- [ ] แอปรันได้ด้วยคำสั่งเดียว
- [ ] มี test อย่างน้อย 1 ชุดและผ่าน
- [ ] มี `CLAUDE.md` ที่สั้นและบอกวิธีรัน
- [ ] อธิบายได้ว่าไฟล์หลักแต่ละไฟล์ทำอะไร (ถ้าอธิบายไม่ได้ → ถาม Claude)

**ต่อยอด (ทำเสร็จเร็ว):** ลากภาพหน้าจอเว็บไซต์ที่ชอบเข้ามา แล้วสั่ง "ปรับ UI ให้มีโทนแบบภาพนี้"
