## 🧪 Lab 1 · แอปแรกจาก prompt

### 🗺️ L1-1 · วางแผนแอป (ใช้ Plan mode)
```text
สร้างเว็บแอป "บันทึกงานประจำวัน" สำหรับทีมอุทยานวิทยาศาสตร์ (ใช้ภายใน ~20 คน)
- Node.js + Express, เก็บข้อมูลเป็นไฟล์ JSON ในโฟลเดอร์ data/, หน้าเว็บ HTML+JS ธรรมดา ไม่ใช้ framework
- งานมี: ชื่อ, ผู้รับผิดชอบ, กำหนดส่ง, ความสำคัญ (ต่ำ/ปกติ/ด่วน)
- หน้าเดียว: ฟอร์มเพิ่มงาน + ตารางรายการ เรียงตามกำหนดส่ง
- UI ภาษาไทย ใช้งานบนมือถือได้
- รันด้วย `npm start` ที่พอร์ต 3001 และมี test ด้วย node:test สำหรับ API เพิ่ม/ดูงาน
เสร็จเมื่อ: test ผ่าน และเปิดเบราว์เซอร์เพิ่มงานได้จริง
วางแผนก่อน บอกไฟล์ที่จะสร้าง ยังไม่ต้องเขียนโค้ด
```

### ✅ L1-2 · ตรวจงานให้จริง
```text
รัน test และรันแอป จากนั้นทดสอบ API ทุกตัวด้วย curl แสดงผลให้ดู
ถ้ามีอะไรไม่ผ่านให้แก้จนผ่าน แล้วสรุปว่าแก้อะไรไป
```

### 🎓 L1-3 · ให้อธิบายจนเข้าใจ
```text
อธิบายโค้ดที่เพิ่งสร้างให้คนที่เขียนโปรแกรมพื้นฐานได้เข้าใจ
ไล่ตั้งแต่ผู้ใช้กดปุ่มเพิ่มงาน จนข้อมูลถูกบันทึกลงไฟล์ อ้างอิงชื่อไฟล์และบรรทัด
```

## ♻️ Lab 2 · ความยั่งยืน

### 🐳 L2-1 · Docker
```text
ทำให้แอปนี้รันด้วย Docker Compose ได้
- สร้าง Dockerfile (node:22-alpine, ไม่รันเป็น root), .dockerignore, docker-compose.yml
- ข้อมูลใน data/ ต้องอยู่ใน named volume ไม่หายเมื่อ down/up
- ค่าที่เปลี่ยนตามสภาพแวดล้อมให้อ่านจาก .env และสร้าง .env.example
- ทดสอบโดย build และ up จริง แล้ว curl ยืนยันว่าทำงาน
```

### 🎁 L2-2 · ชุดส่งมอบ
```text
ตรวจ repo นี้ตาม "Minimum Handover Kit": README.md, CLAUDE.md, .env.example, .gitignore, Dockerfile, docker-compose.yml
สร้างหรือแก้สิ่งที่ขาด README ต้องมีหัวข้อ: ทำอะไร / วิธีรัน / ตัวแปรแวดล้อม / ผู้ดูแล
CLAUDE.md ไม่เกิน 20 บรรทัด ใส่เฉพาะสิ่งที่อ่านจากโค้ดแล้วไม่รู้
ตรวจด้วยว่า .gitignore กัน .env และ data/ แล้ว
```

### 🐙 L2-3 · Commit

## 🔴 Lab 3 · Node-RED

### 🪄 L3-1 · ให้ Claude สร้าง flow
```text
สร้างไฟล์ Node-RED flow (JSON สำหรับ Import) ชื่อ labs/node-red/complaint-flow.json สำหรับ Node-RED 5
- tab ใหม่ชื่อ "Complaint Triage"
- http in: POST /complaint รับ { "text": "..." }
- function: สร้างคำขอไป Claude Messages API (https://api.anthropic.com/v1/messages)
  headers: x-api-key จาก env.get("ANTHROPIC_API_KEY"), anthropic-version: 2026-10-21, content-type: application/json
  model จาก env.get("CLAUDE_MODEL"), max_tokens 2048, output_config.effort = "low"
  ให้จัดหมวด [ไฟฟ้า, แอร์, ความสะอาด, อินเทอร์เน็ต, อื่นๆ] และความเร่งด่วน [ต่ำ, กลาง, สูง]
  ใช้ output_config.format แบบ json_schema เพื่อให้ได้ JSON ที่ตรงรูปแบบ
- http request: method "use" (อ่านจาก msg.method), return parsed JSON
- function: ตรวจ statusCode และ stop_reason, ดึงเฉพาะ content ที่ type = "text" แล้ว JSON.parse
- http response ส่ง { category, urgency, summary } กลับ
- debug node ทุกจุดสำคัญ
ใช้รูปแบบเดียวกับ labs/node-red/flows.json ที่มีอยู่ (ดูเป็นตัวอย่าง)
```

## 🟢 Lab 5 · Agent App

### 🗑️ L5-1 · เครื่องมือลบงานแบบต้องยืนยัน (ง่าย ⭐)
```text
เพิ่มเครื่องมือ delete_task ใน apps/agent-app/tools.js ตามรูปแบบของ registry เดิม (strict schema)
กติกา: agent ต้องแสดงงานที่จะลบและถามยืนยันผู้ใช้ในแชทก่อนเรียกเครื่องมือเสมอ
ใส่กติกานี้ทั้งใน description ของเครื่องมือและ system prompt ใน agent.js
อธิบายด้วยว่าการยืนยันผ่าน prompt อย่างเดียวมีข้อจำกัดอะไร และถ้าจะบังคับจริงในโค้ดควรทำอย่างไร
```

### 📚 L5-2 · ค้นความรู้จากเอกสาร (กลาง ⭐⭐)
```text
เพิ่มเครื่องมือ search_knowledge ใน apps/agent-app
- อ่านไฟล์ .md ทั้งหมดในโฟลเดอร์ apps/agent-app/knowledge/ (สร้างตัวอย่าง 3 ไฟล์: ระเบียบการเบิกค่าเดินทาง, บริการของอุทยานวิทยาศาสตร์, FAQ ห้องประชุม)
- ค้นด้วยคำสำคัญแบบง่าย คืนผลไม่เกิน 3 ส่วนที่เกี่ยวข้องพร้อมชื่อไฟล์
- ปรับ system prompt ให้ตอบคำถามเรื่องระเบียบจากเครื่องมือนี้เท่านั้น และอ้างชื่อไฟล์ที่มา
- ตรวจว่าเส้นทางไฟล์ไม่หลุดออกนอกโฟลเดอร์ knowledge/
```

### 🏢 L5-3 · จองห้องประชุม (กลาง ⭐⭐)
```text
เพิ่มเครื่องมือ list_rooms และ book_room ใน apps/agent-app
- ห้อง 3 ห้อง จองเป็นช่วงเวลา (วันที่, เวลาเริ่ม, เวลาสิ้นสุด) ห้ามจองซ้อน — ตรวจในโค้ด ไม่ใช่ให้ AI ตรวจ
- เก็บข้อมูลใน DATA_DIR เหมือน tasks
- เขียน test ด้วย node:test สำหรับกติกาห้ามจองซ้อน และเพิ่มคำสั่ง npm test
```
